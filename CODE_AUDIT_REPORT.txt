DATA FLOW EXAMPLE: Adding an Expense
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. User enters data in GUI:
   - Title: "Lunch"
   - Amount: "250"
   - Category: "Food"
   - Date: "2026-10-27"

2. User clicks "+ Add Expense" button

3. FinanceTrackerApp.addExpense() triggered:
   - Gets text from titleField → "Lunch"
   - Gets text from amountField → "250"
   - Gets selection from categoryCombo → "Food"
   - Gets text from dateField → "2026-10-27"

4. Validation in FinanceTrackerApp:
   - Check if fields are empty
   - Check if amount is numeric
   - Check if amount > 0
   - Check if category is selected

5. If validation passes:
   new Expense("Lunch", 250.0, "Food", "2026-10-27")

6. Call DatabaseExpenseManager.saveExpense(expense):
   - Extract: title="Lunch", amount=250.0, category="Food", date="2026-10-27"
   - Get Connection via DatabaseConnection.getConnection()
   - Query: "SELECT category_id FROM categories WHERE category_name = 'Food'"
   - Convert date string to java.sql.Date
   - Execute: "INSERT INTO expenses (title, amount, category_id, expense_date) VALUES ('Lunch', 250.0, 2, 2026-10-27)"

7. Upon success:
   - clearFields() empties all input fields
   - loadExpensesFromDatabase() refreshes from database
   - Show success dialog

8. loadExpensesFromDatabase():
   - Call DatabaseExpenseManager.getAllExpenses()
   - Returns ArrayList with all expenses including the new one
   - Call refreshTable()

9. refreshTable():
   - Clear table display
   - Add each expense as row to table
   - Calculate totals
   - Update summary labels


DATA FLOW EXAMPLE: Loading Application at Startup
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

   - Create new ExpenseManager()
   - Create new empty ArrayList<Expense> expensesList
   - Create new empty ArrayList<Expense> filteredList
   - Call setupGUI() to create GUI components
   - Call loadInitialData()

4. loadInitialData():
   - Get categories: DatabaseExpenseManager.getCategories()
     - Connect to Supabase via DatabaseConnection.getConnection()
     - Query: "SELECT category_name FROM categories ORDER BY category_name"
     - Returns: ["Bills", "Education", "Entertainment", "Food", "Other", "Shopping", "Travel"]
   - Populate categoryCombo dropdown with these categories
   - Call loadExpensesFromDatabase()

5. loadExpensesFromDatabase():
   - Get all expenses: DatabaseExpenseManager.getAllExpenses()
     - Connect to Supabase
     - Query with JOIN: "SELECT e.title, e.amount, c.category_name, e.expense_date FROM expenses e JOIN categories c..."
     - Returns: ArrayList of all Expense objects
   - Add all expenses to expensesList
   - Call refreshTable()

6. refreshTable():
   - Clear table
   - For each expense, add row to table
   - Calculate totals and update summary cards

7. app.setVisible(true) displays the window

20 LIKELY VIVA QUESTIONS WITH ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Q: What is the purpose of the Expense class?
   A: The Expense class is a data model that encapsulates expense information 
      (title, amount, category, date). It has private fields for data protection 
      and public getter methods for accessing them.

2. Q: How is encapsulation implemented in this project?
   A: We use private fields in the Expense class (title, amount, category, date) 
      and provide public getter methods. This prevents direct modification of 
      data from outside the class, ensuring data integrity.

3. Q: Why does FinanceTrackerApp extend JFrame?
   A: JFrame is a Swing component that creates a window. By extending it, our 
      FinanceTrackerApp inherits all window functionality (sizing, positioning, 
      closing) without writing that code ourselves.

4. Q: What is the role of DatabaseConnection.java?
   A: It manages JDBC connections to Supabase PostgreSQL. It loads the driver, 
      validates environment variables, and provides a static getConnection() 
      method for other classes to get database connections.

5. Q: How are database credentials kept secure?
   A: Credentials are read from environment variables (SUPABASE_HOST, 
      SUPABASE_PORT, etc.) rather than hardcoded in the application. 
      This prevents exposing passwords in source code.

6. Q: What is the difference between ExpenseManager and DatabaseExpenseManager?
   A: ExpenseManager is in-memory management (stores in ArrayList, not used much 
      in our app). DatabaseExpenseManager handles persistence to Supabase, executing 
      SQL queries for saving and retrieving expenses.

7. Q: How does the application handle adding a new expense?
   A: User fills the form and clicks "+ Add Expense". The addExpense() method 
      validates input, creates an Expense object, calls DatabaseExpenseManager.
      saveExpense() to insert into database, then reloads all expenses from the 
      database to update the display.

8. Q: What SQL operations does the application perform?
   A: Mainly SELECT (to read categories and expenses with JOIN), INSERT (to save 
      new expenses), and WHERE clauses (to filter by category name). Also uses 
      ORDER BY to show newest expenses first.

9. Q: How does the search functionality work?
   A: When user clicks "Search" after typing a term, the refreshTable() method 
      filters the expense list. It checks if expense title or category contains 
      the search term (case-insensitive). Matching expenses are displayed in table.

10. Q: What is a PreparedStatement and why do we use it?
    A: PreparedStatement is a secure way to execute SQL queries. It separates SQL 
       code from data using ? placeholders and setString(), setDouble() methods. 
       This prevents SQL injection attacks.

11. Q: How are database resources properly closed?
    A: We use try-with-resources statements (Java 7+ feature). Connections, 
       PreparedStatements, and ResultSets are automatically closed when try block 
       exits, even if exceptions occur.

12. Q: What happens if a required environment variable is not set?
    A: The DatabaseConnection.getConnection() method checks all five variables 
       and throws SQLException with a message listing missing ones. User sees 
       error dialog: "Error loading categories: Missing environment variables: ..."

13. Q: How is the transaction history table populated?
    A: When app starts or after adding expense, loadExpensesFromDatabase() calls 
       DatabaseExpenseManager.getAllExpenses() which returns ArrayList of Expense 
       objects. refreshTable() iterates through list and adds each as table row.

14. Q: What is the purpose of the static initializer block in DatabaseConnection?
    A: The static block { Class.forName("org.postgresql.Driver"); } loads the 
       PostgreSQL JDBC driver when DatabaseConnection class is first used. This 
       happens automatically before any connection attempt.

15. Q: How does validation work when adding an expense?
    A: Validates: fields not empty, amount is numeric, amount > 0, category 
       selected. If date format is invalid (not YYYY-MM-DD), database throws error 
       "Invalid date format". Category is checked against database.

16. Q: What is a JOIN and how is it used in this project?
    A: JOIN combines data from multiple tables. Our SELECT query uses INNER JOIN 
       to combine expenses table with categories table: 
       "FROM expenses e JOIN categories c ON e.category_id = c.category_id"
       This gets the category name for each expense.

17. Q: Why do we use ArrayList instead of regular arrays?
    A: ArrayList is dynamic - it grows automatically as we add expenses. With 
       arrays, we'd need to know the size in advance. ArrayList provides methods 
       like add(), clear(), size() that are convenient for our use case.

18. Q: How does the application calculate summary statistics?
    A: In refreshTable(), we iterate through filtered expenses: sum all amounts 
       for total, count expenses for transaction count, collect unique categories 
       using ArrayList.contains() to check if already added.

19. Q: What is abstraction and how is it used?
    A: Abstraction hides complex implementation details. Example: DatabaseConnection.
       getConnection() - users just call it, they don't see driver loading, URL 
       building, or environment variable validation logic inside.

20. Q: How would you add update functionality to this project?
    A: Would add: (1) DatabaseExpenseManager.updateExpense() method with UPDATE 
       SQL query, (2) Edit button in FinanceTrackerApp to populate form fields 
       with existing data, (3) Update button instead of Add, (4) Get expense ID 
       from database to identify which to update.
